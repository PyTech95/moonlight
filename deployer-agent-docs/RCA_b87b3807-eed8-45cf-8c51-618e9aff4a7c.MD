# RCA — Deploy run b87b3807-eed8-45cf-8c51-618e9aff4a7c (launch-pad-416)

## Outcome
Deploy failed at **pull_source** (first pipeline step). Nothing was built, promoted, or taken live — this is an initial deploy, so the app has never gone live.

## Failure
`pull_source` activity error:
```
prepare build context: read envs: read env file backend/.env:
open /tmp/agent-env-...-/app/backend/.env: no such file or directory
```

## Root cause
The deployer's `pull_source` step packages the source from the agent-env pod and, as part of preparing the build context, reads every env file declared in the template's `config.yaml` `env_paths` — for the `fastapi_react_mongo_shadcn_base_image` (farm) template that is `backend/.env` and `frontend/.env`.

**`/app/backend/.env` does not exist in the source environment.** The step cannot read a file that isn't there, so it fails before any archive is produced (that is also why no eph sandbox / source archive exists for this run).

This is a **source-environment issue**, not a deployment-manifest bug:
- The farm template legitimately requires `backend/.env` — it is where the FastAPI backend's runtime secrets (`MONGO_URL`, `DB_NAME`, and any app keys) are read from and captured into the deployment's secret store.
- Removing `backend/.env` from `env_paths` to "get past" the step would let the build proceed but would silently drop all backend secrets, producing a backend that can't reach Mongo and fails at runtime. That is not an acceptable fix.

## Required fix (owned by E1 / source environment)
1. Create `/app/backend/.env` in the preview/source environment.
2. Populate it with the backend's required variables — at minimum `MONGO_URL` and `DB_NAME`, plus any other keys the FastAPI app reads via `os.environ` / `python-dotenv`.
   - A typical farm backend expects: `MONGO_URL=...`, `DB_NAME=...`.
   - Confirm against `backend/server.py` / config for any additional keys the code reads.
3. Verify the file exists and is non-empty: `ls -l /app/backend/.env`.
4. Re-trigger the deployment. `pull_source` will then find the file, capture the backend env, and the pipeline can proceed.

## Note
A plain retry WITHOUT creating the file will fail identically — the error is deterministic (missing file), not a transient infra blip, despite the activity-level `retryable:true` flag.
